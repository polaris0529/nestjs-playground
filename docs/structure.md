# 폴더 구조 규칙 (Structure)

이 문서는 저장소의 폴더/파일 구조를 결정하는 **규칙**만 정의한다.
특정 소스 파일을 나열하거나 개별 분류를 지정하지 않는다.
프론트엔드와 백엔드에 **공통으로 적용되는 원칙**을 정한다.

## 공통 원칙 (Frontend + Backend)

- **1차 분류 기준은 도메인(기능)이다.** 파일 타입(controller, service, view, api 등)이 아니라 도메인으로 먼저 나눈다.
- **2차 분류 기준은 계층/역할이다.** 도메인 폴더 내부에서만 타입/계층으로 다시 나눈다.
- **소속 판단 기준** — "이 파일을 삭제할 때 몇 개의 도메인이 영향을 받는가?"
  - 한 도메인만 영향 → 그 도메인 폴더 안에 둔다.
  - 둘 이상의 도메인이 영향 → 공통 영역(`shared/`)에 둔다.
- **진입점·부트스트랩·전역 설정**은 도메인에 속하지 않으므로 최상위 또는 지정된 설정 폴더에 둔다.
- **빈 껍데기 폴더/파일을 미리 만들지 않는다.** 실제로 필요할 때 생성한다.
- 도메인 이름은 **단일 개념을 나타내는 명사**를 사용한다(예: `auth`, `calendar`, `admin`).
- 폴더·파일 이름은 **kebab-case**를 사용한다.
- 하나의 파일이 여러 도메인 로직을 담지 않는다. 도메인이 커지면 도메인 폴더 내부에서 분리한다.

## 요청 프리픽스 규칙 (Frontend + Backend)

- **모든 API 요청 경로는 3뎁스 규칙을 따른다:** `/api/<도메인>/<요청 구분>`.
  - **1뎁스(접두)**: 항상 `api` 로 고정한다.
  - **2뎁스**: 도메인 이름(예: `auth`, `calendar`, `admin`).
  - **3뎁스**: 해당 도메인 안에서 요청을 구분할 수 있는 명명 규칙(리소스/행위 식별자).
- **백엔드**: 전역 프리픽스를 `api` 로 설정한다(`app.setGlobalPrefix('api')`). 프리픽스 밖에 두어야 하는 경로(예: Swagger 문서, 정적 자원)만 예외로 명시한다.
- **프론트엔드**: vite proxy 는 `'/api'` **단일 항목만** 유지한다. 도메인이 추가돼도 proxy 설정을 수정하지 않는다.
- 이 규칙의 목적은 vite config 를 단순하게 유지하는 것이다. 도메인 경로를 하나씩 나열하지 않는다.
